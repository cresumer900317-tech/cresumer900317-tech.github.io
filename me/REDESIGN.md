# /me 리디자인 설계 문서 (v2)

작성 2026-05-17 · 상태: **초안 — 합의 대기** · 결정 시 이 문서가 작업 기준

---

## 0. 한 줄 정의

한국 직장인·엔지니어를 위한 **개인 운영체제(Personal OS)**.
업무·프로젝트·일정·기록·자기계발을 *하나의 흐름*으로 운영하는 곳.
협업 도구가 아니라 **1인 운영 도구**다.

## 1. 핵심 원칙 — 모든 결정을 이걸로 판단한다

1. **프로젝트가 중심.** 캘린더·간트·로그는 프로젝트/할 일을 비추는 *뷰*다.
2. **추가보다 제거.** 메뉴·색·카드는 줄이는 게 기본값.
3. **흐름 우선.** 화면이 아니라 "입력 → 실행 → 기록 → 회고"가 이어져야 한다.
4. **절제된 다크.** 색 1개, 여백 크게, 경계선 최소. "뺄 게 없어서 고급."

## 2. 정보 구조 (IA)

### 현재 — 7탭 평면
대시보드 · 할일 · 프로젝트 · 캘린더 · 간트 · 하루로그 · 영어
→ 전부 동등한 메뉴처럼 보이지만 실제 중요도는 동등하지 않다.

### 개편 후 — 4탭 + 보조
- **탑 내비: 홈 · 프로젝트 · 캘린더 · 로그**
- 우상단: 검색(⌘K) · 설정(아이콘)
- 간트 → 프로젝트 상세 안의 **타임라인 뷰**
- AI 브리핑 → 홈 안의 한 블록
- 영어 → 홈 안의 **습관 카드** (자기계발 surface — 프로젝트가 아니므로 내부로 못 넣음)
- 할 일(Tasks) → **독립 탭 없음.** 홈(오늘·이번주) + 프로젝트(내부) + 캘린더(날짜별)로 접근
- 받은 메모 → 이미 제거 완료 (할 일로 흡수)

근거: 매일 여는 건 홈, 깊게 들어가는 건 프로젝트, 캘린더·로그는 보조, 간트는 표현 방식. 메뉴 위계가 이 사실을 반영해야 한다.

## 3. 객체 모델

### Project = 작은 워크스페이스 (이름 하나가 아니다)
목표(goal) · 기간(start/end) · 진행률 · 소속 Task 목록 · 활동 로그 · AI 요약 · 색

### Task
- 소속: project (선택, 없으면 "미분류")
- **start_date + due_date** ← 지금은 due만 있음. *간트가 죽어있는 핵심 원인*
- parent_task_id (하위 작업 / 체크리스트)
- status · priority · tags · notes · sort_order

### View — 저장 객체가 아니라 task/project를 비추는 것
- 캘린더 뷰 = task를 날짜축으로
- 타임라인(간트) 뷰 = task를 기간축으로, 프로젝트별 묶음
- 보드 뷰 = status축

### Log = 하루 단위 기록. 완료한 task가 자동으로 흘러들어올 수 있다.

> **선행 작업(dependency)은 의도적으로 v2로 미룬다.** 1인 도구에서 의존성 그래프는 과투자. 먼저 "기간 있는 task"만으로 간트를 살리고, 진짜 필요해지면 그때 추가.

## 4. 화면 정의

### 홈
목적: 들어오면 3초 안에 — *오늘 뭘 / 뭐가 늦었나 / 뭐가 중요한가*.
- 히어로: 인사 + D-day + 올해 진행률 — 유지
- **오늘의 실행** — 가장 큰 블록. 오늘 할 일 + 지연된 것. 시각적 압도적 1순위
- 위험 신호 — 마감 임박 / 지연 프로젝트. 작게, 빨강 점으로만
- 습관 — 영어(오늘의 표현 + 스트릭). 작은 카드
- AI 브리핑 — 한 줄
- 빠른 입력 — 상단 고정
- 제거: 위젯 8개 평면 나열 → 위계로 재배치

### 프로젝트 목록 → 프로젝트 상세
상세 = 탭형 워크스페이스: **목표 / 작업 / 타임라인 / 캘린더 / 로그 / AI 요약**

### 캘린더
task의 start~due를 날짜에 표시. 프로젝트 색 사용.

### 로그
하루 로그. 그날 완료한 task 자동 초안 (auto-template 이미 있음 — 활용).

## 5. 디자인 언어 — 다크 + 극도의 절제

**색**
- 배경/표면 3단계만 (bg / surface / elevated)
- 텍스트 3단계 (strong / body / meta) — 4번째 dim 폐지
- 액센트 인디고 1개 — 버튼·활성탭·링크에만
- 상태색(빨강/노랑/초록)은 "면"으로 쓰지 않는다. 4px 점 / 가는 텍스트로만

**선·면**
- 경계선 거의 제거 → 표면 밝기 단차로 구분
- 카드 그림자 1종류. hover lift 같은 장식 절제
- radius 일관 (16)

**여백·타이포**
- 섹션 간 간격 크게 (32~40px)
- 타이포 4단 위계 엄수: 페이지 제목 / 섹션 / 본문 / 메타
- 숫자는 tabular

**모션** — 등장 페이드 1종. 그 외 최소.

## 8. 슬라이스 계획 — 각각 독립 배포

| | 내용 | 백엔드 | 끝나면 |
|---|---|---|---|
| **S1** | 메뉴 7→4탭. 간트/영어/브리핑 제자리로. 홈 위계 재배치. 디자인 언어(절제) 적용 | X | "하나의 제품" 느낌 |
| **S2** | 스키마 변경(start_date, parent_task_id). 프로젝트 상세 페이지(목표/작업 트리) | O | 프로젝트가 워크스페이스 |
| **S3** | 간트·캘린더를 task 기반 뷰로 재구성. 프로젝트 상세 안 타임라인/캘린더 | O | 간트가 살아남 |
| **S4** | task 완료 → 로그 자동. AI 회고. task↔calendar↔project↔AI 연결 | O | 흐름 완성 |

각 슬라이스는 끝나면 배포 → 직접 보고 판단.

## 9. 아직 열린 결정 (착수 전 정할 것)

1. "전체 할 일" 뷰를 홈에 둘지(뷰 토글) — 안 둘지
2. 프로젝트 상세를 별도 페이지로 vs 모달 확장으로
3. 영어를 홈 카드로만 vs 작은 전용 화면도 유지
